## 一、核心认知误区（本次最大浪费时间点）
1. **Sophus 是 header-only 纯头文件模板库**，不需要执行`make`编译出库文件`libSophus.a`、不需要`make install`安装，仅配置头文件检索路径即可编译运行；
2. CMake 的相对路径层级极易出错，固定写**绝对路径**最稳定；
3. C++ 代码内文件相对路径 `./` 参照**终端执行程序的当前目录**，不是cpp源码存放目录；
4. GCC15 校验规则严苛，Sophus自带test测试代码会大量报错阻塞编译，学习阶段无需编译测试用例。

## 二、逐个问题 + 对应可直接复制的解决方案代码/命令
### 问题1：#include "sophus/se3.hpp" 提示找不到文件
#### 可用固定 CMakeLists.txt（ch4目录下直接全覆盖）
```cmake
cmake_minimum_required(VERSION 3.5)
project(useSophus)

# Eigen固定系统路径
include_directories(/usr/include/eigen3)
# Sophus 写死绝对路径，不会路径解析出错
include_directories(/home/lhc/slambook/3rdparty/Sophus)

add_executable(useSophus useSophus.cpp)
# Sophus为头文件库，无需链接静态库，删掉所有link Sophus语句

add_subdirectory(example)
```
#### 一键清理缓存+编译命令（复制整条执行）
```bash
cd /home/lhc/slambook/ch4
rm -rf build && mkdir build && cd build
cmake ..
make
```
#### 运行useSophus程序
```bash
# 必须在ch4根目录运行二进制文件
cd /home/lhc/slambook/ch4
./build/useSophus
```

### 问题2：运行 trajectoryError 报txt文件找不到、断言崩溃
报错：groundtruth.txt / estimated.txt 不存在，核心转储
#### 方案1（推荐，不改代码）运行命令，直接复制执行
```bash
cd /home/lhc/slambook/ch4
./build/example/trajectoryError
```
#### 方案2（永久修复，修改代码文件路径）
打开 `example/trajectoryError.cpp`，替换文件路径字符串
```cpp
// 原代码
// string groundtruth_file = "./example/groundtruth.txt";
// string estimated_file = "./example/estimated.txt";

// 修改为绝对路径
string groundtruth_file = "/home/lhc/slambook/ch4/example/groundtruth.txt";
string estimated_file = "/home/lhc/slambook/ch4/example/estimated.txt";
```
修改后重新编译即可在任意目录运行程序。

### 问题3：尝试安装Sophus到/opt隔离目录，include文件夹生成、lib文件夹缺失
原因：Sophus本身不会生成.a库，install操作无意义；GCC高版本编译测试代码报错中断构建流程。
**最优处理：直接废弃隔离目录安装方案，只保留源码文件夹即可使用Sophus，无需任何编译安装操作**。
Sophus文件夹只需要保留原始解压源码，不用进入build执行任何make/install。

### 问题4：编译Sophus时出现deprecated、array-bounds、deprecated-copy各类告警报错
处理方式：完全不用编译Sophus本体，告警源头为test代码，学习阶段不需要编译Sophus。

## 四、本次踩坑收获
1. 区分两类库：普通静态库（需要编译出.a+链接）、头文件库（仅头文件路径即可使用，Sophus/Eigen均为此类）；
2. 调试路径报错优先打印CMake变量、使用绝对路径排查问题；
3. 不要盲目跟着“库安装到自定义隔离目录”操作，简单场景项目内嵌第三方源码最省心。
